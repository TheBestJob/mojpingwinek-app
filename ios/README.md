# Mój Pingwinek — iOS application (SwiftUI + WKWebView)

The iOS app is in this **same repository** as the web demo and Android APK. It runs the hosted **5.2** web UI using Apple's WKWebView with persistent browser storage.

## What is shared with Android / Web

- Firebase Authentication accounts, login and sessions
- Firestore calendar, journal and (after publishing `firestore-v5.2.rules`) test passport, diagnoses, medications and specialists
- Supabase document uploads, listing and deletion through the Firebase-authenticated Cloudflare Worker
- Same server data across devices, with Internet connection

The **5.2** website is `https://thebestjob.github.io/mojpingwinek-app/v5.2.html`.

## How to build and test

1. GitHub → **Actions** → **Build Mój Pingwinek iOS**. The GitHub-hosted macOS runner generates an Xcode project with XcodeGen, compiles an **unsigned iOS Simulator build**, and uploads `MojPingwinek-iOS-Simulator`.
2. To work locally on a Mac: install Xcode and XcodeGen; from `ios/` run `xcodegen generate`, open `MojPingwinek.xcodeproj`, select an iPhone simulator and Run.
3. For installation on a physical iPhone, open the Xcode project on a Mac, select an Apple Development Team and configure an available unique Bundle ID. An Apple account can support certain local development tests, but distribution via TestFlight or App Store requires Apple's paid Developer Program and applicable signing setup.
4. A production `.ipa` file and TestFlight delivery are **not** generated by the unsigned simulator workflow. To release, set up signing certificates and provisioning profiles in an approved secure CI environment.
5. Sign in to a **fictional test Firebase account**, test calendar and journal across browsers/phones, test medical test forms (only after deploying `firestore-v5.2.rules`), and test document upload/download/delete from the app on a real iPhone. File downloads depend on WKWebView/WKDownload behaviour and must be tested on device.

## Limitations & security

- **This is a native SwiftUI shell around the existing website**, not a complete native rewrite. App Store review may reject minimal web wrappers that don't offer sufficient app-like functionality.
- The hosted site can update independently of the iOS binary. The iOS app needs network access.
- The present web interface and backend are **test-only**; they are not appropriate for real child medical data until comprehensive privacy, consent, access control, audit, export and deletion features are implemented and independently tested.
- Before Store submission: complete medical privacy/legal review (GDPR), Apple privacy labels, privacy policy, support contact, user-initiated account deletion, app icon, screenshots, app metadata, accessibility and functional testing.
- The native host opens only the allowed GitHub Pages site internally. External https links are passed to Safari. Firebase and Supabase API calls are issued from the web app to their existing endpoints.
- Google Calendar integration remains **excluded** as requested.
